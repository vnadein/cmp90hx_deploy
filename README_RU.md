# CMP 90HX Full Deploy Script

> [English](README.md) | **Русский**

## Обзор

Этот скрипт автоматизирует полный процесс развёртывания **NVIDIA CMP 90HX** — майнингового GPU, превращая его в высокопроизводительный AI-ускоритель для инференса LLM. Он объединяет знания из трёх исследовательских проектов сообщества, чтобы снять аппаратные ограничения и оптимизировать производительность инференса больших языковых моделей.

## Что делает этот скрипт

| Этап | Действие | Источник |
|------|----------|---------|
| 1 | Устанавливает системные зависимости (cmake, git, python3, инструменты сборки) | — |
| 2 | Скачивает и запускает `cmpunlocker v0.1.28` для разблокировки PCIe Gen3 + Compute | [pearlfortune/cmpunlocker](https://github.com/pearlfortune/cmpunlocker) |
| 3 | Проверяет статус разблокировки (`PASS_CMP90HX_ALL_TARGETS_FULL_SPEED`) | [pearlfortune/cmpunlocker](https://github.com/pearlfortune/cmpunlocker) |
| 4 | Клонирует `llama.cpp`, применяет патч DP2A, компилирует с CUDA sm_86 | [ggml-org/llama.cpp#24616](https://github.com/ggml-org/llama.cpp/issues/24616) |

## Предыстория: зачем это нужно

**CMP 90HX** — это GPU на базе GA102 (тот же кремний, что и у RTX 3080) с искусственными ограничениями:

| Параметр | Заводской CMP 90HX | После разблокировки |
|----------|--------------------|----------------------|
| Скорость PCIe | Gen1 x1-4 (~0.85 ГБ/с) | **Gen3 x16 (~16 ГБ/с)** |
| Инструкция DP4A | Урезана в 16 раз | **Обход через патч DP2A** |
| Генерация токенов | ~30-50 t/s | **~100-120 t/s** |
| FP32 Compute | Заблокировано eFuse (1/32 скорости) | Разблокировать нельзя (аппаратно) |

### Ключевые выводы исследований

Из [WildFlash1st/cmp90hx-unlock](https://github.com/WildFlash1st/cmp90hx-unlock) (август 2026):

- **Скорости выдачи SM для FP32/INT8 зашиты в аппаратные eFuse** — программная разблокировка невозможна
- **Модификация VBIOS бесполезна** для разблокировки вычислительных ядер
- **Инструкция DP4A урезана в 16 раз**, но **DP2A не урезана**
- **HFMA2 (FP16) CUDA-ядра не урезаны** — доступно 59.5 TFLOPS
- Обходное решение: заменить DP4A на эмуляцию DP2A в llama.cpp для 2x ускорения декодирования

## Использование

### Полное развёртывание в первый раз

```bash
sudo ./cmp90hx-deploy.sh --all
```

После перезагрузки (разблокировка временная) повторите шаг разблокировки, чтобы восстановить состояние.

### Проверка статуса GPU

```bash
sudo ./cmp90hx-deploy.sh --status
```

### Пересборка llama.cpp (после обновления upstream)

```bash
sudo ./cmp90hx-deploy.sh --rebuild
```

### Запуск бенчмарка

```bash
sudo ./cmp90hx-deploy.sh --benchmark
```

### Установка только зависимостей

```bash
sudo ./cmp90hx-deploy.sh --deps
```

## Требования

- **ОС:** Linux x86_64 (протестировано на HiveOS, Ubuntu, Debian)
- **GPU:** NVIDIA CMP 90HX (PCI ID 10de:220d или 10de:1555)
- **Драйвер:** NVIDIA Open Kernel Modules 580.159.03 или 610.43.03
- **CUDA:** установлен CUDA Toolkit
- **Secure Boot:** отключён
- **Права:** требуется root-доступ

## Ожидаемая производительность после развёртывания

Бенчмарк Llama-2-7B Q4_0 (`llama-bench -p 512 -n 128 -ngl 99`)

| Метрика | Заводской CMP 90HX | После скрипта | RTX 3080 (справ.) |
|---------|--------------------|----------------|-------------------|
| pp512 (обработка промпта) | ~374 t/s | ~378 t/s | ~3009 t/s |
| tg128 (генерация токенов) | ~57 t/s | ~114 t/s | ~78 t/s |

Примечание: генерация токенов (tg) на CMP 90HX с патчем DP2A превышает RTX 3080 благодаря более высокому использованию пропускной способности памяти на этапе декодирования.

## Технические детали

### Механизм разблокировки PCIe (pearlfortune/cmpunlocker)

Двоичный файл `cmpunlocker-rs`:

- Обнаруживает все карты CMP 90HX по PCI ID
- Временно выгружает драйвер NVIDIA
- Модифицирует регистры конфигурации GPU для включения PCIe Gen3
- Перезагружает драйвер с разблокированной конфигурацией
- Состояние сохраняется до следующей перезагрузки

### Механизм патча DP2A (llama.cpp)

Патч модифицирует `ggml/src/ggml-cuda/common.cuh`:

- **До:** используется интринзик `__dp4a()` (урезан в 16 раз на CMP 90HX)
- **После:** при компиляции с `-DDISABLE_DP4A` заменяется на:
  - 2x `prmt.b32` (перестановка байтов)
  - 2x `dp2a.lo` / `dp2a.hi` (двойное упакованное умножение-накопление)
- **Результат:** 4 инструкции вместо 1, но каждая работает на полной скорости → итог в 2 раза быстрее

### Почему FP32 нельзя разблокировать

Из анализа eFuse (WildFlash1st, 8 авг 2026):

- Модификаторы скорости выдачи SM хранятся в аппаратных eFuse по адресам `0x8207d4-0x8207ec`
- Значения: `0x5` = делитель 1/32 скорости для путей FP32/INT8
- Попытки записи через `GPU_EXEC_REG_OPS` молча игнорируются кремнием
- Прошивка GSP-RM подписана RSA-3K, Booter проверяется в SECURE IMEM
- **Вывод:** требуется физическая модификация eFuse — программно невозможно

## Устранение неполадок

| Проблема | Решение |
|----------|---------|
| `nvidia-smi` не найден | Установите NVIDIA Open Driver |
| Checksum MISMATCH | Удалите `/var/tmp/cmpunlocker-deploy/` и повторите |
| Unlock NOT confirmed | Перезагрузитесь и запустите `--unlock` снова |
| `common.cuh` не найден | Структура llama.cpp изменилась; обновите патч вручную |
| CUDA Toolkit не найден | `sudo apt install nvidia-cuda-toolkit` |
